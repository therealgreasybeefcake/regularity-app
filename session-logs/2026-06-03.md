## V2.0 Overhaul — Monorepo, Backend, Auth Cutover (Phases 0–3)

Kicked off a full V2.0 overhaul. Goals: (1) sleek visual redesign, (2) BetterAuth
+ OAuth, (3) Railway Postgres instead of localstorage, (4) real-time web live-view,
(5) improved reporting, (6) general reliability hardening.

Locked decisions: Hono API on Railway + Expo Web live-view in a pnpm+Turborepo
monorepo · BetterAuth (Google + Apple + email/password) · Railway Postgres (Drizzle)
· migrate existing data on first login · "Pit Wall" dark/data-dense visual direction.

Plan file: `~/.claude/plans/i-want-to-do-composed-dewdrop.md`.

### Phase 0 — Monorepo foundation (committed `3bdcab9`)
- Converted to **pnpm + Turborepo**. Installed pnpm 11.5.1 (no corepack). `.npmrc`
  with `node-linker=hoisted` + `shamefully-hoist=true` for Expo/Metro compatibility.

### Phase 1 — Backend (committed `3bdcab9`)

### How to run
- API: `pnpm api` (root) → http://localhost:8787 (reads `apps/api/.env`).
- App: `cd apps/mobile && npx expo run:ios` (first native build), then `npx expo start`.
  Simulator uses `localhost:8787`; physical device needs `EXPO_PUBLIC_API_URL`=LAN IP.
- Don't run `pnpm dev` (turbo) for the app — it double-starts Metro; use two terminals.
